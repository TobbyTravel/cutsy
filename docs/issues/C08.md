## Problem
Cute audio must be brief, controllable and nonintrusive.

## Expected behavior and implementation boundaries
Create eight original PCM WAV effects at build time; record source/license; implement one reusable cancellable output service with gain and device recovery; use 10% default, 90s ambient and 5s interaction cooldown; never overlap cues.

## Dependencies
[C04](https://github.com/TobbyTravel/cutsy/issues/5), [C07](https://github.com/TobbyTravel/cutsy/issues/8)

## Acceptance checklist
- [ ] All eight cues packaged and previewable
- [ ] no startup/footstep loops
- [ ] mute and quiet stop immediately
- [ ] controlled peaks and soft envelopes
- [ ] no-device and device-change paths recover
- [ ] sound failure cannot crash mascot.

## Required verification
Follow [TESTING.md](https://github.com/TobbyTravel/cutsy/blob/main/docs/TESTING.md), selecting the scenarios applicable to this issue. Add automated tests for deterministic core/validation behavior and manual evidence for desktop behavior. Record commit, pack hash when relevant, commands, observed results and untested scenarios. Do not close merely because the code builds.
