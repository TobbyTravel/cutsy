## Problem
Finish a runnable distribution with evidence, not just a successful build.

## Expected behavior and implementation boundaries
Publish self-contained win-x64 EXE with embedded default pack and editable portable ZIP; automate publish/checksums; clean-user smoke test; full manual matrix; measure CPU/memory and two-hour handle/GDI/memory soak; document unsigned reputation and native extraction.

## Dependencies
[C01](https://github.com/TobbyTravel/cutsy/issues/2), [C02](https://github.com/TobbyTravel/cutsy/issues/3), [C03](https://github.com/TobbyTravel/cutsy/issues/4), [C04](https://github.com/TobbyTravel/cutsy/issues/5), [C05](https://github.com/TobbyTravel/cutsy/issues/6), [C06](https://github.com/TobbyTravel/cutsy/issues/7), [C07](https://github.com/TobbyTravel/cutsy/issues/8), [C08](https://github.com/TobbyTravel/cutsy/issues/9), [C09](https://github.com/TobbyTravel/cutsy/issues/10)

## Acceptance checklist
- [ ] EXE needs no installed .NET/admin/developer tools
- [ ] ZIP includes pack and instructions
- [ ] integrity and paths pass
- [ ] results record hardware/commit/hash
- [ ] performance targets measured
- [ ] missing scenarios explicitly untested
- [ ] artifacts linked in release issue.

## Required verification
Follow [TESTING.md](https://github.com/TobbyTravel/cutsy/blob/main/docs/TESTING.md), selecting the scenarios applicable to this issue. Add automated tests for deterministic core/validation behavior and manual evidence for desktop behavior. Record commit, pack hash when relevant, commands, observed results and untested scenarios. Do not close merely because the code builds.
