## Problem
Prove Windows transparency, interaction and focus behavior before investing in the full content engine.

## Expected behavior and implementation boundaries
Build the small native layered overlay with a reviewed sprite, tray, context menu, body hit mask, no-focus activation, mouse capture and drag/drop; handle mixed DPI and monitor origins; use a minimal floor surface for the first proof.

## Dependencies
[C01](https://github.com/TobbyTravel/cutsy/issues/2)

## Acceptance checklist
- [ ] Other-process controls remain clickable through transparency and decorative effects
- [ ] body clicks react
- [ ] >=4 logical pixel movement drags
- [ ] grab offset preserved
- [ ] typing focus retained
- [ ] tray recovery works
- [ ] DPI and capture-loss tests recorded.

## Required verification
Follow [TESTING.md](https://github.com/TobbyTravel/cutsy/blob/main/docs/TESTING.md), selecting the scenarios applicable to this issue. Add automated tests for deterministic core/validation behavior and manual evidence for desktop behavior. Record commit, pack hash when relevant, commands, observed results and untested scenarios. Do not close merely because the code builds.
