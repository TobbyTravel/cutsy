## Problem
Behavior must be editable and portable without hardcoded pose chains.

## Expected behavior and implementation boundaries
Implement PACK_FORMAT v1, JSON Schema, immutable validated packs, path/size/ID checks, seeded scheduler and fake clock, core movement primitives, capability eligibility, cancellation and atomic last-good reload; implement pack validation CLI and define concrete resource limits.

## Dependencies
[C01](https://github.com/TobbyTravel/cutsy/issues/2)

## Acceptance checklist
- [ ] Valid minimal example runs through deterministic tests
- [ ] malformed and escaping paths rejected
- [ ] missing optional sound degrades gracefully
- [ ] invalid reload keeps prior pack
- [ ] zero-time loops bounded
- [ ] core imports no Windows/UI/filesystem dependencies.

## Required verification
Follow [TESTING.md](https://github.com/TobbyTravel/cutsy/blob/main/docs/TESTING.md), selecting the scenarios applicable to this issue. Add automated tests for deterministic core/validation behavior and manual evidence for desktop behavior. Record commit, pack hash when relevant, commands, observed results and untested scenarios. Do not close merely because the code builds.
