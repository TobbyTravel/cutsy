## Problem
Make the mascot usable without editing app code and recoverable when settings/content are wrong.

## Expected behavior and implementation boundaries
Implement size/activity/audio, Stay here, pause, gaming mode, app exclusions, optional startup, reload/preview, restore defaults, recover position, single-instance controls, bounded logs and versioned settings; implement portable/local-app-data policy.

## Dependencies
[C03](https://github.com/TobbyTravel/cutsy/issues/4), [C04](https://github.com/TobbyTravel/cutsy/issues/5), [C05](https://github.com/TobbyTravel/cutsy/issues/6), [C06](https://github.com/TobbyTravel/cutsy/issues/7), [C07](https://github.com/TobbyTravel/cutsy/issues/8), [C08](https://github.com/TobbyTravel/cutsy/issues/9)

## Acceptance checklist
- [ ] Defaults match product
- [ ] settings survive restart
- [ ] read-only portable errors understandable
- [ ] invalid packs preserve working state
- [ ] editing guide examples validated
- [ ] startup remains opt-in
- [ ] second launch opens controls.

## Required verification
Follow [TESTING.md](https://github.com/TobbyTravel/cutsy/blob/main/docs/TESTING.md), selecting the scenarios applicable to this issue. Add automated tests for deterministic core/validation behavior and manual evidence for desktop behavior. Record commit, pack hash when relevant, commands, observed results and untested scenarios. Do not close merely because the code builds.
